# Web 信息收集与攻击面梳理

## 适用场景

- 用户第一次给一个本地 / 内网授权目标，需要做一轮系统性的信息收集；
- 用户说「先摸一下这个站」「看看攻击面」「做一轮侦察」，且不希望直接打攻击载荷。

## 执行步骤

1. **确认范围**：调用 `get_current_context`，确认项目目标、靶场状态与授权范围；公网目标必须拒绝。
2. **被动信息收集**：调用 `run_web_scan`，`profile=recon`，拿到指纹、DNS、端口、TLS、安全头等结果。
3. **暴露面梳理**：根据侦察结果整理：技术栈 / 开放端口 / 子域 / 接口 / 敏感信息 / 配置缺陷。
4. **按需深挖**：用户同意后再用 `run_web_scan` 的 `modules` 参数做专项（`files` 敏感文件、`secrets` 密钥、`api` 接口安全、`web` 主动漏洞）。
5. **结论**：调用 `get_results` 汇总，输出风险按严重级排序 + 下一步建议。

## 输出要求

- 先给结论（目标是否可达、关键攻击面有哪些），再给证据（请求路径 / 回显摘要）；
- 每条发现必须带：位置（URL/参数）、证据、风险等级、修复建议；
- 不夸大结果：扫描器未覆盖的部分要明确标注「需人工复核」。
